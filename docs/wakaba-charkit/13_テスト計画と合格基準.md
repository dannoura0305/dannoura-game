# 13 テスト計画と合格基準

数値の線は**最初の目安**（実機・人の目で見て直す）。直した時は本書の表と `metrics.mjs` の版（`formulaVer`）を一緒に上げる。
「人が見る」項目は AI が合格と書かない（`pass: null` のまま人へ・mapkit `07` §7 と同じ）。

---

## 1. 自動の数値と合格の線

### 1.1 動き
| 項目 | 測り方 | 合格の線（目安） |
|---|---|---|
| **足の滑り** | 足が「着いている」こま（足の高さ ≤ 地面＋2cm かつ 足の速さ ≤ 30cm/s、またはクリップの `contacts`）の間の、足（つま先とかかとの 2 点）の**水平の速さ**の平均と 95 パーセンタイル | 平らな地面：平均 **≤ 2cm/s**・p95 ≤ 5cm/s／坂・階段：平均 ≤ 4cm/s・p95 ≤ 8cm/s |
| 足の浮き・めり込み | 着いている間の足の裏と地面の高さの差 | 浮き ≤ 2cm・めり込み ≤ 2cm |
| **切り替えのはね（ポップ）** | 状態が切り替わる前後 3 こまの、各関節の角速度の跳ね（前後の平均との差） | 体の関節 **≤ 15°/こま**（60fps）・根の位置の跳ね **≤ 1cm** |
| ループの継ぎ目 | ループの最後と最初のこまの姿勢の差 | 関節 ≤ 3°・根の高さ ≤ 0.5cm |
| ふるえ | 関節の加加速度の外れ値の割合 | ≤ 1% |
| 体の傾き | 坂での体の傾きの角度（性格の値の係数と比べる） | 係数 ± 20% |
| 歩幅の伸縮 | クリップの再生の速さの倍率 | 0.7〜1.4 を外れたら警告（不自然になる） |

P13（2026-10-17）で足した数値（`charkit/anim/metrics.js`・`tests/shinshoku-p13-motion.test.mjs`）：
| 項目 | 測り方 | 合格の線 |
|---|---|---|
| ひざのはね | 60Hz のひざの曲げの 1 こまの差・2 階の差・最小 | ≤40°/こま・≤40°/こま²・最小 ≥1.5°（伸びすぎなし） |
| 周期の継ぎ目・飛び | 1 周期 240 点の骨の回りの 1 段・その差 | 最後と最初 <0.05°・1 段 ≤10°・2 階 ≤8°（足の裏返り・腰の落ちを見つける） |
| 腰の上下 | 1 周期の腰の高さの幅 | 歩き 1.3m/s 2〜7cm・2.2m/s ≤9cm・走り ≤10cm。片脚の真ん中＞着地の後 |
| 骨盤と肩 | 着地の時の骨盤の回りの符号・骨盤と胸の世界の回りの相関・頭の回り | 着地の脚の側が前・相関 < −0.9・頭 < 骨盤の半分 |
| 腕 | 左腕がいちばん前の位相・前後の振り・ひじの遅れ | 0.45〜0.7・前＞後ろ・遅れ >0 |
| 止まりの一歩 | 止まった時に着いていた足の、前半の動き・動く時の高さ | ≤1cm・動く時は持ち上げる |
| 法線の継ぎ目 | 同じ位置・同じ材質の頂点の法線のずれ（3° 超）の割合 | <2% |
| 髪の流れ | 2.2m/s で歩く時のポニーテールの先の向き（下から） | <60°・走りの方が大きい |

### 1.2 めり込み・揺れ物
| 項目 | 測り方 | 合格の線 |
|---|---|---|
| **髪・服のめり込み** | 揺れ物の骨の先と体の当たり（カプセル）の中に入った深さ・こまの割合 | 深さ 5mm を超えるこまが **≤ 1%**・最大 ≤ 2cm |
| 腕と体のめり込み | 腕のカプセルと胸・腰のカプセル | 走り・戦闘で最大 ≤ 1.5cm |
| 揺れの行き過ぎ | 揺れ物の骨の休みからの角度の最大 | ≤ `secondary.maxAngleDeg`（だんのうら 70°） |
| 落ち着くまで | 急に止まってから揺れが 5° 以内に収まるまで | ≤ `secondary.settleS`（0.8 秒）× 1.5 |

### 1.3 顔・口
| 項目 | 測り方 | 合格の線 |
|---|---|---|
| **口のずれ** | 母音の始まりの時刻（文字 → 母音の場合は字幕の文字が出る時刻／声がある時は音の立ち上がり）と、口の形の重みが 0.5 を超える時刻の差 | 平均 **±40ms 以内**・最大 ±80ms（目安として、音が先に聞こえるずれの方が気づかれやすいので、口が 40ms を超えて遅れない） |
| 母音の当たり（声がある時） | 利用者の「あいうえお」の録音で、正しい口の形が最大の重みになったこまの割合 | ≥ 80% |
| 瞬き | 1 分あたりの回数・1 回の長さ | 性格の値 ± 30%・100〜200ms |
| 表情の切り替え | 重みの変化の速さ | 0→1 が 80ms 以上（ぱっと変わる演出は印をつけて除外） |

### 1.4 戦闘
| 項目 | 測り方 | 合格の線 |
|---|---|---|
| **当たりのこまの一致** | クリップの `hitStart`・`hitEnd` と `data/combat.js` の startup・active | **0 こまのずれ**（伸縮で合わせた後） |
| 入力から動き始め | ボタンの入力のこまから、体の関節が動き始めたこま | **≤ 2 こま**（60fps）。今の手続きアニメより悪化しない |
| 取り消しの窓 | `cancelOpen` と fighter の取り消しの規則 | 一致 |
| 伸縮の倍率 | 区間ごとの時間の伸縮 | 0.6〜1.6（外れたら作り直し） |

### 1.5 性能
| 項目 | 測り方 | 合格の線 |
|---|---|---|
| fps（実機・PC） | `?perf=1`（利用者の PC・1080p・ultra／high） | 平均 60・1% の最低 ≥ 45 |
| fps（実機・スマホ） | 同（low） | 平均 30 以上 |
| キャラクターの CPU の時間 | 混ぜる係＋IK＋揺れ＋表情（`performance.now` で計る） | 主人公 PC ≤ 1.0ms・スマホ ≤ 2.5ms |
| 描画呼び出し・三角形・テクスチャの量 | `renderer.info`（今の `__sh.debug.renderInfo()`） | `10` §1 の段の表 |
| GPU のメモリ（目安） | テクスチャの大きさの合計（計算）＋実機のブラウザの GPU の情報（取れる時） | `10` §1 |
| 読み込み | モデル＋基本のモーションの束の転送量・時間 | 主人公 ≤ 8MB（KTX2・gzip 後）。スマホの起動は今より +1 秒以内 |

### 1.6 モデル・データ
| 項目 | 合格の線 |
|---|---|
| gltf-validator | エラー 0（警告は理由を記録） |
| 標準骨格 | 必須の骨がそろう・`ext_` の名前の規則・指 30 本 |
| 三角形・材質・テクスチャ | `10` §1 |
| 表情 | VRM の標準＋`expressions.custom` の全部がある |
| スキーマ | `character.json`・モーションの meta が検査を通る |
| 権利の門 | 作品が参照する全部が pass |

## 2. 人が見る項目（動画で）
| 項目 | 見方 |
|---|---|
| 男性に見えるか・設定と合っているか | 三面図・4 場面の撮影・会話の場面 |
| 歩き・走り・止まりの自然さ | 決まった道の動画（§4）を 0.5 倍でも見る |
| 性格の値が効いているか | 同じ道で「ふつう／緊張／疲れ／恐れ」の 4 本を並べる |
| 表情・口・視線の自然さ | 会話の場面 1 分 |
| 戦闘の手触り | 実際に遊んで（実機） |
| 陰影：屋内・屋外・夜・逆光で読めるか・背景と浮かないか | `lookdev.html` の 4 場面 |
- 点数は 1〜5（`07` §3.1 の `quality.human`）。

## 3. 前後比較
- 変更の前のコミットと後のコミットで、**同じ場面・同じカメラ・同じ入力の記録**を撮り、左右に並べた動画と数値の差の表を PR に付ける。
- 入力の記録：`tools/charkit/inputs/<名前>.json`（こまごとの移動の向き・ボタン）。乱数の種は固定。

## 4. 動画での確認の作り方

### 4.1 Web（Three.js）：こま送りの撮影（実機の速さに左右されない）
- **P13 で実装**：`tools/charkit/motion_lab.html`＋`tools/charkit/capture.mjs`（`node tools/charkit/capture.mjs --out <dir> [--only walk,run] [--keep]`）。ゲーム全体ではなく、ゲームの役者（Player・CompanionActor）を場面の入力の時間割で動かす（下の 1〜5 は将来ゲームそのものを撮る時の手順）。
1. ゲーム（または `testyard.html`）を `?capture=1&fixedDt=1/60&seed=…&input=walk_course.json` で開く。
2. `capture=1` の時、ゲームは**時計を止め**、Playwright が `__ck.step()` を呼ぶたびに **1/60 秒だけ進めて描く**（ソフト描画で 1 こまに時間がかかっても、動きは正確）。
3. 各こまを PNG で保存（`page.screenshot`）＋同じこまの骨の位置を JSON に記録（数値の検査はこちらで行う＝画像に頼らない）。
4. ffmpeg で動画にする：`ffmpeg -framerate 60 -i f_%05d.png -c:v libx264 -pix_fmt yuv420p out.mp4`。前後比較は `-filter_complex hstack`。
5. Playwright の `recordVideo` は**使わない**（ソフト描画では 4〜6fps になり、動きの確認にならない。`docs/wakaba-mapkit/01` §3.1）。
- 費用：1 秒の動画＝60 こま。ソフト描画で 1 こま 0.3〜1 秒の見込み → 10 秒の動画で数分（未計測）。

### 4.2 実機（利用者の PC）
- 同じ `capture=1` を利用者の PC のブラウザで行えば、実機の描画で同じ動画が撮れる（`tools/charkit/capture.mjs` を利用者の PC で実行）。fps の計測は `capture=0`＋`perf=1` で別に行う。

### 4.3 UE（試しの時）
- Movie Render Queue で決まったカメラの動画を書き出す（`04` §4）。数値の検査は骨の動きを FBX で書き出して同じ `metrics` に通す。

## 5. 試験の場所と頻度
| 段 | 何を | どこで | いつ |
|---|---|---|---|
| 単体 | スキーマ・骨の対応・権利の門・数値の計算（足の滑りの計算そのものを、答えが分かっている作り物のデータで試す） | `node tests/run.mjs`（クラウド・CI） | 毎回 |
| 結合 | 試験用 glTF のクリップの再生・混ぜる係・IK の収束 | node（DOM なしの部分）＋Playwright | 毎回 |
| 動画 | 決まった道・決まった会話・決まった戦闘の撮影と数値 | Playwright（クラウド） | PR ごと（重いので変更があった時だけ） |
| 回帰 | 境界侵食の既存の試験・通しプレイ（`tools/shinshoku_play.mjs`） | クラウド | 毎回 |
| 実機 | fps・見た目・手触り | 利用者の PC・スマホ | フェーズの終わり |
