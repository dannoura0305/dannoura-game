## 3. データ・API の詳細

### 3.1 骨の対応 `charkit/rig/bonemap.js`
```js
export const VRM_REQUIRED = [/* 17 本＝今の JOINT_NAMES */];
export const VRM_RECOMMENDED = ['upperChest','leftShoulder','rightShoulder','leftToes','rightToes','leftEye','rightEye','jaw', /* 指 30 本 */];
export const PROFILES = { vrm: {...}, ue5: {...}, mixamo: {...}, rigify: {...}, shinshoku17: {...} };  // `04` §3 の表
/** names：モデルの骨の名前、opt.profile：既知の形（無ければ自動判定）、opt.map：手書きの対応 */
export function matchBones(names, map = {}, opt = {}) → { [vrmName]: modelBoneName }
export function detectProfile(names) → 'vrm'|'ue5'|'mixamo'|'rigify'|'unknown'
export function extBones(names) → [{ name, group, part, side, index }]   // ext_ の名前を分解。規則違反は { error }
export function checkSkeleton(found) → { missingRequired:[], missingRecommended:[], fingers:n }
```
- 今の `matchBones(names, map)` の戻り値・挙動は**そのまま**（第 3 引数は任意）。

### 3.2 読み込み `charkit/runtime/load.js`
```js
export async function loadModel(url, opt) → { root, humanoid /* VRM の時 */, J /* vrm 名 → Object3D */, ext, expressions, springs, height, kind:'vrm'|'gltf' }
export async function loadClip(url, model) → THREE.AnimationClip   // .vrma は three-vrm-animation の createVRMAnimationClip、.glb は名前の対応でトラックの名前を書き換え
export function retargetTracks(clip, srcProfile, model) → THREE.AnimationClip   // glb のクリップの骨の名前を model の骨に
```
- VRMA は「normalized の humanoid」に当たる。今の `Poser` も normalized の骨に当てているので、**クリップ → Poser の追加の層**の順で混ぜる（§4.1）。

### 3.3 キャラクターの実行 `charkit/runtime/character.js`
```js
export class CharacterRuntime {
  constructor(model, config /* character.json */, clipdb, opt /* { quality, ground, anchors } */)
  setForm(formId)                         // 'purple'|'white'
  setState({ tension, fatigue, fear })    // 0..1
  setMove({ speed, dirX, dirZ, yawRate, crouch, onGround })   // ゲーム側の移動の結果（遊びの判断はゲーム側）
  play(actionId, opt)                     // 'cmb_katana_light_1' など。opt.fit = { startup, active, recovery }（60Hz のこま）
  say(text, { startAt, charsPerSec })     // 口・表情・会話の手
  lookAt(target | null)
  update(dt)                              // 固定の 1/60 で呼ばれる（main.js の 60Hz のシミュレーションと同じ）
  sample() → { bones: Float32Array, contacts, events }   // 検査・撮影用（capture=1 の時）
}
```
- **ゲームの判定（当たり・無敵・移動の速さ）はゲーム側が決める**。CharacterRuntime は見た目だけ。`events`（足音・当たり始め）は**見た目の印**で、判定には使わない（今の `fighter.js` の数字が正）。

### 3.4 シミュレーションとの時間の合わせ
- `shinshoku/main.js` はシミュレーションを 60Hz 固定で回している（コメントに明記）。CharacterRuntime の `update` もこの固定の刻みで呼ぶ。描画のこまの間は補間しない（簡単さを優先。必要なら後で）。
- `capture=1` の時は時計を止め、`window.__ck.step(n)` で n こま進める（§5）。

## 4. 各係の仕様

### 4.1 混ぜる順番（1 こまの中）
1. 状態機械（`statemachine.js`）が今の状態と遷移の進み具合を決める（入力：`setMove`・`play`）。
2. ブレンドスペース（`blend.js`）が移動のクリップの重みを出す（1D：速さ／2D：速さ × 進む向きと体の向きの差）。
3. 歩幅（`stride.js`）：実際の速さ ÷ クリップの速さ（`anim.speedMS`）で再生の速さを決め、0.7〜1.4 の外は歩幅（脚の振りの角度）で補う。**切り替えは足の位相（`events` の footL/footR）を合わせる**。
4. `AnimationMixer` を進める（`mixer.js`）。
5. 上半身の層（構え・武器・会話の手）を骨の組（マスク）で重ねる。
6. 性格の追加の層（`personality.js` → 腕の振り・腰・背骨・頭の追加の回転、腰の高さ）。
7. IK：腰の高さ → 足 → 手 → 視線（`ik/*`）。
8. 揺れ物（three-vrm の SpringBone）→ 行き過ぎの上限（`limits.js`）。
9. 表情・口・瞬き（`face/*`）・補正の形の重み（骨の角度から）。

### 4.2 状態機械（移動）
状態：`idle`・`start`・`move`・`stop`・`turnInPlace`・`crouchIdle`・`crouchMove`・`jumpStart`・`air`・`land`・`stairs`・`action`（戦闘・ふれる動き）。
- `start`：速さ 0 → 目標の速さで、`accelS` の間 `loco_walk_start` を再生。目標の向きと体の向きの差が `turnInPlaceDeg` を超えたら `turnInPlace` を先に。
- `stop`：入力が 0 になったら、次に着く足に合わせて `loco_walk_stop`（左右）を選ぶ。止まる距離はクリップの根の動きから計算し、ゲーム側の止まる距離との差を `stride` で吸収。
- 遷移の時間：既定 0.15 秒（性格の `reaction.latencyMs` は**見た目の遅れには使わない**＝入力の反応を遅くしない。驚き・被弾の反応の始まりだけに使う）。

### 4.3 性格の値 `personality.js`
```js
export function resolve(personality, state /* {tension,fatigue,fear} */) → flat  // 例 { 'locomotion.walkSpeed': 1.215, ... }
```
- `states.*` の各キー：名前が `Deg`・`M` で終わる物は**足す**（状態の値 0〜1 を掛けて）、他は**掛ける**（1 と倍率の間を状態の値で補間）。キーは `locomotion.walkSpeed` のような点つきの道、または短い名前（`walkSpeed` → `locomotion.walkSpeed` を探す）。
- 試験：恐れ 1.0 で `comHeightOffsetM` が 0 → −0.05、`walkSpeed` が 1.35 → 1.1475 になる、など。

### 4.4 戦闘のクリップの合わせ `combatfit.js`
```js
/** clip の印（hitStart/hitEnd/全長）と data の {startup, active, recovery}（こま）から、区間ごとの時間の対応を作る */
export function fitSegments(events, frames, fps, data) → { map: [[srcT, dstT], ...], scales: [s1, s2, s3], ok: boolean }
/** 根の動きの踏み込みの距離を data.lunge（m）に合わせる倍率 */
export function lungeScale(rootDistM, lungeM) → number
```
- `ok=false`（倍率が 0.6〜1.6 の外）の時は警告を出し、そのまま伸縮して再生（遊びは止めない）。
- 入力から動き始めの保証：`play()` を呼んだこまで、クリップの重みを**0.05 秒で 1 へ**（それより遅く混ぜない）。

### 4.5 揺れ物の上限 `secondary/limits.js`
- three-vrm の SpringBone を `vrm.update(dt)` で動かした後、各鎖の骨の休みの向きからの角度が `secondary.maxAngleDeg` を超えたら戻す。こまごとの角速度も `maxSpeedDegS` で切る（急な回転・ワープでの暴れを抑える）。
- 体の当たり：`character.json` の `colliders` を three-vrm の当たり（球・カプセル）に追加。VRoid の当たりとの重複は名前で避ける。
- ワープ（場面の切り替え・ムービー）の時は `resetSprings()` で休みへ戻す。

### 4.6 補正の形
- `correctives` の各行：骨の今の回転を `axis` の角度にして、`fromDeg`→`toDeg` の間で 0→1 の重みにする（smoothstep）。重みは表情と同じ「モーフの重み」として設定（VRM の表情ではなく網のモーフを直接）。
- three-vrm の表情の仕組みとぶつからないよう、補正の形は表情に登録しない（名前の頭 `cor_` で区別）。

### 4.7 シェーダー `charkit/shader/wakabatoon.js`
```js
export function makeToonMaterial(kind /* 'skin'|'hair'|'cloth'|'metal'|'eye'|'face' */, params /* character.json の materials[...] */, shared /* face, outline, rim, env */) → THREE.Material
export function applyCharacterShader(model, config, opt /* quality */) → { materials, setEnv(sceneLight), dispose() }
```
- 段の陰影：`NdotL` を `threshold`・`softness` で 2〜3 段に（ランプのテクスチャではなく式で。色は `base/shade/shade2`）。
- 顔：`shadowMode: 'sdf'` の時、顔の網だけ `sdfMap`（光の左右で反転）と、頭の前の向き・光の向きの角度を比べて影を決める。`normal_transfer` の時は Blender で転写した法線をそのまま使う。
- 髪：`highlight.tex` を髪の UV で重ね、視線の上下で `viewShift` だけずらす。
- 目：`irisDepthM` だけ視線の向きに UV をずらす（視差）。目の材質は輪郭線なし。
- 輪郭線：今の殻（`skinOutlineMaterial`）を使い、太さを**画面の px で一定**（カメラの距離で割る）・`distanceFade` で細く・頂点色の `vertexWidthChannel` で部位ごとに。
- 環境：`setEnv({ ambient, keyDir, keyColor, fog, grade })` を場面の切り替えの時に呼ぶ。`ambientInfluence`・`minLuma`（最終の明るさの下限）・`backlightRimBoost`（光が後ろの時にリムを強く）。
- MToon の値の変換（`mtoon_map.js`）：VRM の MToon（陰の色・陰のずれ・リム・輪郭線の幅）から `character.json` の初期値を作る。逆向き（書き出し用）も。
- 試験：材質の作成（node では three の材質のオブジェクトだけ作って uniform の値を確かめる）と、`lookdev.html` の撮影（Playwright）。

### 4.8 ふれる動き `interact/anchors.js`
```js
export function approachPose(anchor, charConfig) → { pos:[x,y,z], yaw, handTarget?:[x,y,z], hipTarget?:[x,y,z], clip:'int_door_slide_open_R' }
export function pickClip(anchor, charConfig, available) → clipId
```
- 移動の最後の 0.5m で位置と向きを `approachPose` に合わせる（移動の目標を差し替える）。手は IK で `handTarget` へ（クリップの `grab` の印のこまで重み 1）。

### 4.9 口 `face/lipsync_text.js`
```js
export function toKana(text) → string            // ひらがな・カタカナ。漢字は事前の読み（台詞のデータに読みを持たせる：{ text, ruby }）
export function vowels(kana) → [{ v:'a'|'i'|'u'|'e'|'o'|'n'|'-', mora:1 }]   // 拗音（きゃ）は 1 モーラ・「っ」は口を閉じる・「ー」は前の母音を伸ばす
export function schedule(vs, { startAt, morasPerSec }) → [{ t0, t1, v }]
export const VRM_VISEME = { a:'aa', i:'ih', u:'ou', e:'ee', o:'oh' };
```
- 漢字の読み：自動の読み（形態素の解析）は使わず、**台詞のデータに読み（`ruby`）を持たせる**か、字幕の表示の速さで「口をぱくぱく」（母音は当てない予備）にする。今の台詞のデータの形（`shinshoku/data/events.json` など）を壊さないよう、`ruby` は任意の欄にする。
- 声がある時（将来）：`lipsync_audio.js` が wlipsync で母音の重みを出し、文字からの予定と比べて時刻を合わせる。

## 5. 撮影と数値の道具
- `tools/charkit/capture.mjs`：`node tools/charkit/capture.mjs --page testyard --input walk_course --frames 600 --out /tmp/...`。Playwright でページを開き、`__ck.step(1)` → 画面撮影 → `__ck.sample()` を JSON に追記、を繰り返す。最後に ffmpeg で mp4（`--compare <前の結果のフォルダ>` で左右に並べる）。
- `tools/charkit/metrics.mjs`：`sample` の JSON から `13` §1 の数値を計算して `report.json`（mapkit の `auto.character` の形・`05` §4）を書く。
- ゲーム側のフック：`?capture=1` の時だけ `window.__ck = { step, sample, setInput }` を出す（今の `window.__sh` と同じ考え方。本番の動きは変えない）。

## 7. 試験用のモデル `tools/charkit/make_test_char.mjs`
- 今の `tools/shinshoku_make_test_gltf.mjs` と同じやり方で、**VRM 1.0 の名前の骨（指・目・あご・肩・つま先）＋`ext_hair_ponytail_01〜04`＋箱の網＋短いクリップ 3 本（立ち・歩き・刀の弱）**の glTF を作る（`tests/fixtures/charkit_test.gltf`）。クリップの歩きは、わざと足の滑りを入れた版と入れない版を作り、`metrics` の試験に使う。
- VRM（.vrm）の試験用ファイルは、VRM の拡張（`VRMC_vrm`）を手で書くのは誤りが入りやすいので、**利用者の PC の VRoid で作った素体（自作の設定・規約の確認後）**を使う（`11` 手順 4）。
