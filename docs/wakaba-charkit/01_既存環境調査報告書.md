## 2. 境界侵食（shinshoku）のキャラクターの仕組み【確認済】

### 2.1 コードで組んだキャラクター（手続きの形）
| 部品 | ファイル | 中身 |
|---|---|---|
| スキン網の組み立て | `shinshoku/actor/skin.js`（453 行） | `SkinBody`：骨（`THREE.Bone`）を組み、管・球・箱・髪の房などの部品を**骨の重みつきの頂点**で作り、**1 つの SkinnedMesh（頂点色）＋顔（キャンバスの地図帳 256²）＋裏返しの殻の輪郭線**にまとめる。**1 体あたり描画呼び出し 3 回**。関節の境目は重みを `smooth` で混ぜて滑らかに曲げる。武器・帽子は「専用の骨の大きさを 0 にする」で出し入れ |
| 寸法 | 同 `DIM` | だんのうら（**男性 164cm・細身**）：脚 0.86・肩の幅の半分 0.165・上腕 0.27・前腕 0.235・太もも 0.40・すね 0.385・頭の半径 0.122（m） |
| 骨 | `skin.js`・`rig.js` の `JOINTS` | **17 本**（`hips spine chest neck head`／左右の `UpperArm LowerArm Hand UpperLeg LowerLeg Foot`）。**名前は VRM の humanoid と同じ**。向きは **+Z が前・Y が上・単位 m**。指・つま先・目・あご・肩（shoulder）は**無い** |

### 2.2 手続きのアニメーション
| 部品 | ファイル | 中身 |
|---|---|---|
| 歩き・走り | `actor/anim.js` の `locomotion`・`phaseRate`・`strideAmp` | **進んだ距離で位相を進める**＝足が滑りにくい作り（支える脚が半周期で動く距離 2·L·sin(A) と体の移動を合わせる）。走りは 3.2m/s 超 |
| 立ち | `idle` | 呼吸（胸）・重心の小さな揺れ |
| 状態ごとの姿勢 | `dannouraPose`・`whitePose`・`companionPose`・敵ごと | 構え・連撃・回避の転がり・被弾・倒れる。`mix`／`add` で姿勢を混ぜる |
| 姿勢の当て方 | `actor/rig.js` の `Poser` | 関節ごとの目標の回転（オイラー）へ**毎フレーム slerp で近づける**。休みの姿勢 `rest` を足す |
| 上に重ねる層 | `actor/actors.js` の `Looks`・`Sway` | 瞬き・ひるみ（ばね）・当たった光・揺れ物 |
| 戦闘のこま | `shinshoku/data/combat.js`・`combat/fighter.js` | **60Hz のフレームで発生・持続・硬直**（例：刀の弱 1 段目 startup 6・active 4・recovery 14）、ヒットストップ、回避の無敵 3〜14f、先行入力 10f。**見た目のアニメはこの数字に従う側**（遊びの手触りが先） |

**できていないこと**：IK（足を地面に合わせる・手を物に添える）なし（地面は y=0 の平ら）／モーション素材（クリップ）を使う仕組みは**準備だけ**（`vrm.js` で `animations:"clips"` の時に `AnimationMixer` を作るが、ゲーム側で再生していない）／口の動きは `talk` の絵だけで音に合わせていない／視線（lookAt）なし／指なし。

### 3.1 デザインの注意（重要）
- **だんのうらは男性**（`STORY_BIBLE.md` §2・`docs/kyokai/README.md`）。ところが既存の 2D の絵とイメージ資料は**中性的〜女性的に見える描き方**（長い髪・大きな目・細い首・なで肩）になっている所がある。画像生成 AI は「紫の長髪＋花＋ピンクの帽子」から**女性に寄せて描く傾向**があるため、三面図（`11` §3）では**男性の体の特徴を数値と言葉で固定**する（肩幅＞腰幅・平らな胸・首の太さ・のどの小さな出っ張り・手と足の大きさ・眉の形など）。**女性化は不可**。
- イメージ資料の中の文字（「僕」・仲間の名前・Lv など）は**正史ではない**（`docs/shinshoku/reference/README.md`）。一人称は「アタシ」（オネェ言葉）。
- 白い姿は**女性ではない・別人格ではない・暴走ではない**（`STORY_BIBLE.md` §2）。

## 6. まとめ
1. 境界侵食には「**骨入りのアニメ調キャラクター（コード製）＋手続きのアニメ＋トゥーン＋輪郭線＋VRM／GLB の差し替えの入口**」がすでにある。描画呼び出し 3 回／体という軽さと、足が滑りにくい歩きの考え方は良い土台。
2. 足りないのは、**外部で作った高品質のモデル（顔・髪・服の作り込み）**、**モーションのクリップとその混ぜ方**、**IK・視線・口・表情のモーフ**、**顔影・髪・目の陰影**、**動きの品質を数字で測る仕組み**、**モーションの権利の台帳**。
3. 本物の VRM／GLB はまだ一度も読み込んでいないので、**最初の実験は「VRoid の標準の素体（自作の設定）を 1 体読み込んで、今の仕組みでどこまで動くかを見る」**のが安く確実（`12` フェーズ 2）。
4. クラウドの Claude は GPU が無く、Blender・VRoid・UE を動かせない。**モデルの制作・見た目の判断・実機の fps は利用者の PC**。クラウドはコード・スクリプト・自動検査・文書。
