# コントローラー対応（PC・Android・iOS／GameSir Nova Lite 2 基準）

本編「だんのうら ― 30日間サバイバル育成」を、ゲームパッドだけ・タッチだけ・キーボードだけのどれでも遊べるようにした記録。
**今の動作・画面・セーブデータは変えていない**（セーブの形式は同じ。コントローラーの設定は別のキーに保存）。

---

## 1. 調査結果（既存プロジェクト）

| 項目 | 内容 |
|---|---|
| エンジン | なし（素の HTML／CSS／JavaScript）。本編は DOM、ミニゲームは canvas（1 本は three.js の 3D） |
| 配布 | GitHub Pages（https）＋ PWA（`sw.js` でオフライン） |
| 既存の入力 | **キーボード操作がほぼ全画面にある**：本編のゆびカーソル（`main/ui.js`）、会話（`main/story.js`）、タイトル・オープニング・エンディング（`main/presentation.js`）、スロット選択、家・庭（`main/home/interactions.js`）、全ミニゲーム（`MG.onKey`） |
| 既存のゲームパッド | 高難易度版の買い出しダッシュだけが `navigator.getGamepads()` を直接読んでいた。別作品の「境界侵食」（`shinshoku/`）は独自に対応済み |
| キーの無い所 | 本編の音楽ゲーム「歌」（タップのみ）、家・庭のマス目のタップ、ドラッグ中心のミニゲーム（運営会議・夜食の盛り付け・ディフェンスの配置・脱出の調べる場所） |
| 文字入力 | 家・庭の名前付け（`HOME.ui.prompt`）、境界事象・境界ノアリスの名前入力 |
| 画面の向き | 縦長（480px の列）前提。manifest は縦固定だった |

→ **入力 API は Gamepad API を採用**（ブラウザ・PWA のまま 3 OS に届く）。既存のキー操作を活かし、
ゲームの処理には手を入れずに「ゲームパッド → 共通アクション → 既存のキー操作」へ橋渡しする設計にした。

## 2. 設計

```
Gamepad API ──► input/input-manager.js（INPUT）
                 ・ボタン番号・軸・ABXY 配置の違いを吸収 → 論理ボタン（A B X Y LB RB LT RT SELECT START L3 R3 十字 HOME／LX LY RX RY）
                 ・共通アクション（confirm cancel status menu help tabPrev tabNext fast cursor …）
                 ・接続／切断、最後に使った入力（pad／touch／kbm）、振動、遅延の計測、学習した割り当て
              ──► input/profiles.js（操作の型：画面・ミニゲームごとの「論理ボタン → キー」表）
              ──► input/pad-ui.js（画面への橋渡し）
                 ・合成した KeyboardEvent を既存のキー処理へ（受け取られなければ予備のフォーカス移動）
                 ・仮想カーソル（タップ・ドラッグが要る所）、一時停止メニュー、操作方法、切断時の一時停止
                 input/vkeyboard.js（ゲーム内キーボード）／input/diag.js（診断）
```

- ゲームの進行ロジックは Gamepad API を直接読まない。例外の 2 本（3D 工場のアナログ移動・視点、高難易度版ダッシュ）も `INPUT` 経由に変えた。
- **ミニゲームごとの操作**：開始すると `INPUT.pushProfile()` で専用の型に替わり、終わると外して本編の型へ戻る（押したままのキーは全部離す）。
  新しいミニゲームは `registerMinigame({ …, pad: { move, keys, help } })` と書けば、その型が使われる。
- **決定ボタンの位置**は設定で「下（A・×）」「右（○・Nintendo の A）」を選べる。表示名は機種の流儀（Xbox／PlayStation／Nintendo）で変わる。

### 共通の操作（本編）

| ボタン（Xbox 表記） | 働き |
|---|---|
| 左スティック・十字キー | 項目を選ぶ |
| A | 決定・会話を送る |
| B | キャンセル・閉じる |
| Y | ステータス |
| LB／RB | メニュー切替（メイン・工場・配信・状態・スキル。窓にタブがあればタブ） |
| RT（押している間） | 会話・オープニングの早送り（選択肢で止まる） |
| 右スティック | スクロール |
| R3 | 仮想カーソルの出し入れ（どこでも押せる予備の手段） |
| Menu（START） | 一時停止メニュー：再開・操作方法・セーブ・ロード・ステータス・設定・コントローラー設定・診断・タイトルへ |
| View（SELECT） | 操作方法（いまの画面の型を表示。ほかの画面の型も見られる） |

各ミニゲームの割り当ては `input/profiles.js`、ゲーム内では View で見られる（ミニゲームの見出しのヒントもパッド表記に替わる）。

## 4. モバイル

- `viewport-fit=cover` にして、主な画面をセーフエリア（切り欠き・ホームバー）の内側へ（`style-pad.css`）。
- **横画面**（高さ 560px 以下）では本編のメイン画面を 2 列に：左＝今日の目標・場面・会話、右＝選択肢。一時停止メニューも 2 列。
- manifest の向きを `portrait` → `any` に（ホーム画面から起動しても横にできる。縦の見た目は今のまま）。
- タッチ・キーボード・ゲームパッドは、最後に触った物で自動で切り替わる（`body.input-pad／input-touch／input-kbm`）。焦点の枠と仮想カーソルはパッドの時だけ。
- 遊んでいる最中にコントローラーが外れたら、ミニゲームを一時停止して知らせる（再接続して A、またはタップで再開）。

## 5. 診断画面

`gamepad.html`（単独）か、一時停止メニュー →「ゲームパッド診断」。
ボタン（論理名と番号）・スティック・トリガーの深さ・生の値・接続／切断の記録・**割り当ての学習**（非標準の機種で 1 つずつ押す）・
入力遅延の目安（読み取り間隔、コントローラーの更新時刻→読み取り、反応テスト）・振動テスト（対応環境のみ）。

## 6. 制約・注意（ブラウザの仕様によるもの）

1. **iPhone・iPad（Safari）**：Apple の GameController 対応機（MFi・Xbox Wireless・DualShock 4・DualSense など）しか見えない。
   Nova Lite 2 は iOS 向けのモードで接続する想定（**実機未確認**）。どの端末でも「ボタンを一度押すまで」コントローラーが見えないことがある。
2. **振動**：Chrome・Edge の `vibrationActuator`（dual-rumble）がある環境だけ。無い環境では診断画面にそう出る（ゲームは振動なしで動く）。
3. **音の開始**：ブラウザによっては、ゲームパッドのボタンが「ユーザーの操作」とみなされず、最初の音を出すのに画面タップかキーが一度要る場合がある。
4. **Android**：機種・ブラウザによっては B ボタンが「戻る」として扱われ、ページを離れる可能性がある（要実機確認。起きる場合は PWA としてホーム画面から起動するか、決定ボタンの位置の設定で回避を検討）。
5. Gamepad API は https（GitHub Pages）か localhost で使う。
6. タッチ端末では、ミニゲームの画面に描いたタッチ用ボタンはパッド使用中も表示されたまま（各ゲームの描画は変えていない）。

### ネイティブアプリ化との比較

| 方式 | 良い点 | 悪い点 | 判断 |
|---|---|---|---|
| **ブラウザ／PWA＋Gamepad API（採用）** | 今のまま配れる・3 OS 共通のコード・更新が即時 | iOS は対応機のみ、ボタン＝ユーザー操作にならない場合、Android の戻る問題 | 標準ボタン・スティック・トリガーは全部取れるので、まずこれ |
| Capacitor（Android／iOS の WebView 包み） | ストア配布、戻るボタンを自分で止められる、ネイティブの GameController へ橋渡しできる | ビルド環境（Xcode・Android Studio）・審査・二重管理 | 実機で 4. や 1. が問題になった時の第一候補 |
| Electron／Tauri（Windows） | 全画面・Steam 配布 | 中身は同じ Chromium（Gamepad API）なので入力の差はほぼ無い | 入力のためには不要 |
| Godot などで作り直し | ネイティブの入力 | 全画面の作り直し | 不採用 |

## 7. 検証

### 自動（この環境で実施済み）
- `node tests/input-manager.test.mjs`：配置の吸収（標準・ハット軸・学習した割り当て）、遊び、トリガー、接続／切断、複数台、決定ボタンの入れ替え、型の積み替え、遅延の計測、全ミニゲームに型があること。
- `node tests/e2e/pad-playthrough.cjs [幅x高さ]`（Playwright・偽のゲームパッド）：**コントローラーだけで**
  タイトル → プロローグ → 本編 → メニュー切替・ステータス → 一時停止メニュー（セーブ・ロード・設定・操作方法・診断）→ 全ミニゲーム（専用の型・一時停止・終了）→
  切断で一時停止・再接続で再開 → 歌 → 家・庭とゲーム内キーボードで名前入力 → 最終日 → エンディングの最後の画面。
  844×390（横）・390×844（縦）・1280×720（PC）の 3 つで 48/48 合格。
- 既存のテスト 93 本もすべて合格。

> 30 日を最初から最後まで 1 回で通す確認は時間がかかるため、自動では「最終日にしてからエンディングまで」を確かめている。
