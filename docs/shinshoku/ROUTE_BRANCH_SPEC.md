# ROUTE_BRANCH_SPEC — ルート分岐の状態と記録

状態：**提案**。企画書の確定事項：2ルート（妖力解放／正体秘匿）、状態の明示管理、**分岐理由を再現できる**こと、**手掛かり1つの取り逃しでルートが閉じない**こと、分岐にセーブ地点。

## 1. 方針
1. 分岐は**第4章の1か所だけ**。それより前のプレイで分岐が勝手に決まることはない（隠しポイントで決めない）。
2. 分岐は**プレイヤーのはっきりした選択**で決まる。選択肢は両方とも**いつも選べる**（取り逃しや成績で消えない）。
3. 第1〜3章では白い姿は自由操作できない（演出の一瞬だけ）。だから「うっかり白い姿を使って秘匿ルートが消える」ことは起きない。
4. 分岐の直前に**専用のセーブ地点**（自動セーブ＋手動セーブ枠の案内）。クリア後は**章選択**から分岐をやり直せる。
5. 分岐の理由は `branchLog` に機械が読める形で残る。同じセーブと同じ入力からは同じ結果になる。

## 2. 状態変数（`shinshoku_save_v1` の `story` の中）

## 3. 分岐の場面（第4章 `ch04` step `branch`）
```
前提：ch04 の必須（異常ログ・研究者の放送）を終えている → 地下で相棒が囲まれる
  ① 自動セーブ（slot 'branch'）＋「ここで物語が分かれます」とは**言わない**（ネタばらしを避け、セーブ画面に「分岐前」の印だけ）
  ② 選択（時間制限なし）：
       「化けを、解く」         → reveal
       「このまま、人として戦う」 → secret
  ③ secret を選んだ場合：紫の姿だけの高難度戦闘「人の姿の試練」
       負けたら：同じ戦闘をやり直し（直前から）。3回負けたら案内：
         [もう一度] [手助けあり（敵の数−1・見切りの窓+50%。記録に残る）] [選択に戻る]
       ※「選択に戻る」は②に戻るだけ。勝手に reveal にはしない
  ④ ルート確定：route / routeLock / branchLog に書く → 自動セーブ
```
- 分岐場面の前後で、相棒の信頼・解決の仕方は**台詞だけ**を変える。

## 4. 分岐記録 `branchLog`（再現用）
```json
{
  "seq": 1,
  "kind": "route_lock",
  "chapter": "ch04", "step": "branch",
  "decision": "secret",
  "via": "choice",                 
  "trial": { "attempts": 2, "assist": false, "result": "win" },
  "rulesVer": 1,
  "saveVer": 1,
  "gameVer": "0.1.0",
  "seed": 918273,
  "at": "2026-10-14T12:00:00.000Z",
  "snapshot": { "trust": 62, "docs": 14, "yokaiUses": 0 }
}
```
- `via`：`choice`（選択）／`chapter_select`（クリア後の章選択からのやり直し）／`load_branch`（分岐前セーブの読み込み後の再選択）。
- 再選択しても古い記録は消さず追記（`seq` を進める）。現在のルートは最後の `route_lock`。
- `snapshot` は理由の説明用（「なぜこのルートか」の画面で見せる）。**判定には使わない**。
- デバッグ：`?route=reveal|secret&ch=ch05A` で分岐後から始める（記録に `via:'debug'`）。

## 5. 詰み防止（両ルート共通）
| 危険 | 対策 |
|---|---|
| 鍵となる物を失う | 鍵・資料は捨てられない・売れない・使い切らない |
| 弾切れで必須戦闘に勝てない | 近接（鉄パイプ・刀）は壊れない。必須戦闘の部屋には弾の最低保証（足りなければ置く） |
| 一方通行で戻れない | 一方通行の扉の先に、元の区画へ戻る道か、必要な物の予備を置く。テストで到達性を検査 |
| 白い姿でしか通れない所 | reveal だけの近道にとどめ、secret には必ず別の道（紫の姿の仕掛け）を用意 |
| 秘匿ルートが難しすぎる | 手助けモード（記録に残るだけで結末は変えない）・難しさ設定 |
| 巨大猫又の場面で負け続ける | 巨大猫又の場面は「やり直し」が直前からで、3回で手助け案内 |
| 分岐前セーブを上書きした | 分岐前セーブは専用枠（上書き不可）。クリア後は章選択 |
| 取り逃した手掛かり | 必須の手掛かりは**複数の場所**に置く（金庫：3か所のどれか1つ）。任意の手掛かりは結末を変えない |
| 他作品を遊んでいない | 他作品由来の手掛かりは**必ず本作の中でも手に入る**（CROSS_GAME_LINK_SPEC） |

## 6. 結末の決まり方
| ルート | 結末 ID | 条件 |
|---|---|---|
| reveal | `end_reveal` | 終章A の最終戦に勝つ |
| secret | `end_secret` | 終章B の最終戦に勝つ |
- 結末は2種（＋両方見たあとの対比の場面）。**本編の9種には一切触れない**（本作の結末を本編の一覧に足さない）。
- 「誰も殺さずに」等の遊び方の違いは結末の種類を変えず、エピローグの一言と実績で表す【提案】。

## 7. テスト（TEST_PLAN にも記載）
- 分岐場面の単体テスト：同じセーブ・同じ入力で同じ `route`・同じ `branchLog`（`at` 以外）。
- 両ルートで「全必須イベントに到達できる」グラフ検査（LEVEL_DESIGN_SPEC の区画グラフ×各章の鍵）。
- secret で白い姿の入力が**無効**であること（入力しても何も起きない・記録されない）。
- 3回負け→手助け→勝利でも `route==='secret'` のまま。
