# CROSS_GAME_LINK_SPEC — 作品間のつながり（データ契約）

区分：方針は **【確定・企画書】**（B を基本に C を一部・硬い依存なし）。契約・項目は **【提案】**。
既存の原則（**【確定・既存】**）：他作品のセーブは**読むだけ**。`kyokai/link.js`（本編を読む）、`main/day31.js`（境界事象の TRUE を読む）がその例。

## 1. つながりの種類
| 種類 | 意味 | 例 | 本作での扱い |
|---|---|---|---|
| **A** 本筋の必須条件 | 他作品を遊ばないと進めない | – | **使わない**（硬い依存の禁止） |
| **B** 物語・遊んだ結果 | 他作品の結果で、台詞・背景・小物・資料の一部が変わる | 本編の結末→本作の自宅の小物 | **基本** |
| **C** アイテム・能力・調査結果 | 他作品の結果で、本作の道具や手掛かりが早く手に入る | 境界事象の記録→金庫の手掛かり | **一部**。必ず本作の中でも手に入る（同じ物・同じ強さ） |

## 3. 解放表（ID 方式・データ駆動）
`shinshoku/data/unlocks.js` に「条件 → 効果」を並べる。条件は上のアダプタの値だけで書く。効果の種類：`opening`（オープニングの差分）・`titleBg`（タイトル背景）・`bgm`（タイトル曲）・`prop`（自宅などの小物）・`gallery`（ギャラリーの一枚）・`doc`（資料の追記）・`line`（台詞の一言）・`hint`（手掛かりの先出し）。

## 4. 「作中の知識」と「プレイヤーのメタ知識」を分ける
| 区分 | 定義 | 例 | データ |
|---|---|---|---|
| `world` 作中の知識 | 本作の人物が知り得ること。台詞で触れてよい | 町の事件・研究者の記録・事務所の資料 | `docs[].worldFact=true` |
| `meta` メタ知識 | プレイヤーが他作品で見たこと。**作中の人物は知らない** | 本編の結末、境界事象の主人公の名前・B-30、トビネズミの富山 | `unlocks[].meta=true` |
- 規則：`meta` の情報を、作中の人物の台詞で「知っている」ように言わせない。見せ方は小物・背景・付箋（書き手不明）・ギャラリーまで。
- 例：だんのうらは境界事象の主人公を知らない（境界事象の前提）。本作で境界事象の人物を出す場合も、主人公（朝霧）とだんのうらを長く話させない（Q4-b）。

## 7. テスト
- アダプタ：各キーが「無い・壊れたJSON・古い形」でも例外を出さず「無い」を返す（node）。
- 解放表：本編の9種の ID が `game.js ENDING_LIST` と一致する（ずれたら失敗。`main/day31.js` の TYPES と同じ照合）。
- 他作品のキーに**一度も書かない**ことを、`localStorage` の差分で確認（Playwright：本作を通しで遊ぶ前後で `dannoura_*`・`kyokai_*`・`tobi_*` が同じ）。
- 他作品のデータがまったく無い状態で、本作が最後まで遊べる（通しの自動プレイ）。
