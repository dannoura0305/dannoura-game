## 1. 層
| 層 | 道具 | 対象 | いつ |
|---|---|---|---|
| ① ロジック | node（`tests/shinshoku-*.test.mjs`、依存なし。ES Modules を import、または node:vm） | 入力の窓・ダメージ・AI の状態・分岐・セーブの移行・アダプタ・解放表・区画グラフ・台詞の原文照合 | 毎回 |
| ② 画面つき自動プレイ | Playwright（`tools/shinshoku_play.mjs`）＋ Chromium（ヘッドレスで WebGL2＝SwiftShader を確認済み） | 起動・移動・戦闘の入力列・セーブ/ロード・章の通し・ページエラー・画面撮影 | フェーズの区切り |
| ③ 数での性能 | Playwright で `renderer.info`（描画呼び出し・三角形・テクスチャ数）を読む | 区画ごとの上限（GAME_INTEGRATION_SPEC §6） | フェーズの区切り |

| ⑤ 遊んでの確認 | 利用者・開発者 | 怖さ・手触り・物語 | フェーズの区切り |

## 2. ロジックのテスト（主なもの）
| テスト | 中身 |

| `shinshoku-graph` | 区画グラフ×鍵：各章・各ルートで必須の場所へ到達できる。一方通行の先から戻れる |

| `shinshoku-giant` | 暴走の場面の入力表に「市民を攻撃する」操作が無い |
| `shinshoku-data` | 敵・武器・資料・解放表のデータの形（必須の項目・ID の重複なし・参照切れなし） |

## 3. 自動プレイ（Playwright）
| シナリオ | 画面 | 確認 |
|---|---|---|
| 起動〜商店街の端まで | PC 1280×720、スマホ横 844×390（タッチ） | ページエラー0、壁抜けなし、5秒以内に操作可 |

| 帰路を救う／倒す | PC・スマホ | 救った個体が攻撃しない |

| 章の通し（自動 API `__sh.debug.*` で移動を短縮） | PC | 各章の必須イベントを通過、分岐の両方、結末2種 |

| 他作品のキーを書かない | PC | 通しの前後で `dannoura_*`・`kyokai_*`・`tobi_*` が同じ |
| 既存作品への影響なし | PC | 既存の通しテスト（17ミニゲーム・30日・9結末）が引き続きページエラー0 |

## 5. 原文の台詞（一字一句の照合）
| 場面 | 話す人 | 原文 |

- フェーズ8（`tests/shinshoku-p8.test.mjs`・通しプレイ `--only ch7`）：決め台詞は shinshoku/ 全体で 2 回・結末A の原文は `story/cutscenes7.js` の 1 回だけ（`fixed:true`・（相棒））。その間のカメラの鍵（`hair:true`）は、だんのうらの頭の後ろの上から白い髪を見ている（データの検査）。通しプレイでは実際の画面で頭が中央付近・後ろから・上から・白と紫の髪のモデルであることを確かめる。終章A の支えの場面（決め台詞の三度目になりそうな所）で（相棒）は名前を呼ぶ。
