# 06 開発優先順位（フェーズ 0〜6）

**2026-10-17 の決定で並べ直しました：方式 A・B・C を全部採用**（`10`）。2 本の線で進めます。
- **A 線（クラウド・本線）**：ブラウザ版（Three.js）。フェーズ 3〜6 はこれまでどおりクラウドの Claude が作って自動で試験する。写実は試験マップ（山の廃村）だけ（Q-A1 の回答）。

（元の前提＝「まず案 A、UE は試しだけ」は `08` §11 に記録として残す。）
各フェーズは **作業ブランチ → PR → 利用者の承認 → マージ** で区切ります。

## 優先順位の理由
1. **「遊べるか」を先に確かめる**（依頼の最重要条件）。写実の見た目はフェーズ 3 だが、歩ける・塞がない・届くはフェーズ 2 で仮の形のまま固める。
2. **クラウドだけで進められる部分を先に**（フェーズ 1・2）。利用者の PC での作業（導入・素材）はチェックリストへの回答を待つ間に準備する。
3. **n8n は最後**。仕事の数が少ない間は GitHub の PR だけで回るため、自動化の前に手順を固める。
