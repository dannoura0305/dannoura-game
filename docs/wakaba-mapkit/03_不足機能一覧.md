# 03 不足機能一覧

「いま無いもの」を、依頼の項目ごとに並べました。**誰が・どこでできるか**を分けています。
- 〔C〕＝クラウドの Claude Code だけで作れる（コード・スクリプト・文書・自動試験）
- 〔S〕＝Claude がスクリプトを書き、**利用者の PC で実行**する（Blender の bpy・UE の Python・Gaea の CLI など）
- 〔M〕＝**人の手作業**が要る（ソフトの導入・ライセンスの同意・素材の購入/取得・見た目の判断・実機での計測）

優先度：P1＝最初の検証マップ（山の廃村）に必須／P2＝基盤として早めに／P3＝後で。

## 1. 地形
| 機能 | 現状 | 必要なもの | 誰 | 優先 |
|---|---|---|---|---|
| 高さのある地面（山・坂・崖） | 無し（y=0 の平面） | 高さマップ（16bit PNG/RAW）を読む地面の網＋高さを返す関数（当たり判定・配置用） | 〔C〕 | P1 |
| 高さマップの作成 | 無し | Gaea（または Blender の地形アドオン・手続きノイズ）で作り 16bit で書き出し | 〔S〕〔M〕 | P1 |
| 地面の材質の塗り分け（土・草・岩・落ち葉） | 無し | 傾き・高さ・Gaea のマスクから塗り分け（スプラットマップ） | 〔C〕〔S〕 | P1 |
| 川・水路・水面 | 用水路（箱）だけ | 川の曲線（スプライン）→ 地形を削る・水面・岸の当たり | 〔C〕 | P2 |
| 森（木・下草の大量配置） | 木は数本（コード） | 木の glTF＋インスタンス描画＋距離で間引き（LOD） | 〔C〕＋素材〔M〕 | P1 |
| 崖・張り出し | 無し | 崖の岩の網を地形に重ねる（高さマップでは張り出しが作れない） | 〔S〕〔M〕 | P1 |
| 洞窟・トンネル | 無し | 地形とは別の網（モジュール部品）。UE 5.8 の Mesh Terrain は試験段階（検索要約） | 〔S〕〔M〕 | P3 |
| 日本の田畑・棚田・あぜ道 | 「畑」の絵が 1 枠 | 段の地形＋あぜの部品＋水面 | 〔C〕〔S〕 | P3 |

## 2. 建物
| 機能 | 現状 | 必要なもの | 誰 | 優先 |
|---|---|---|---|---|
| モジュール部品（壁・床・扉・窓・階段・屋根）の寸法規格 | 無し（箱をコードで） | 格子（例 0.5m 単位・階高 2.7m）と接続点の規格（`07` §4.4） | 〔C〕 | P1 |
| 部品の作成 | 無し | Blender で作る（bpy で寸法どおりに半自動）／CC0 素材／購入 | 〔S〕〔M〕 | P1 |
| 部品から家を組む生成器 | 町の家はコードの箱 | 間取りの JSON → 部品の配置 | 〔C〕 | P1 |
| 入れる室内（扉の開閉・当たり） | 自宅などは箱で再現済み | 部品の当たり判定（扉の穴）＋扉の状態 | 〔C〕 | P1 |
| 廃屋らしさ（傾き・破損・苔・汚れ） | 無し | 汚れのデカール・壊れた部品の別形・材質の重ね | 〔S〕〔M〕 | P1 |
| 町・工場・研究所・学校・病院・倉庫・地下・ダンジョン | 町の箱だけ | 部品の種類を増やす（P3 で順次） | 〔S〕〔M〕 | P3 |

## 3. 手続きの配置（PCG）
| 機能 | 現状 | 必要なもの | 誰 | 優先 |
|---|---|---|---|---|
| 種（seed）での再現 | 区画単位ではある | マップ全体の種と、層ごとの子の種 | 〔C〕 | P1 |
| 入口・通路を塞がない | 試験で確認している（町だけ） | 「立ち入り禁止の形」（入口の前の扇形・通路の帯）を配置の規則に | 〔C〕 | P1 |
| 浮き・めり込みの検出 | 無し | 部品の底と地面の高さの差を測る | 〔C〕 | P1 |
| 重なりの検出 | 無し（箱の当たりはある） | 置いた物同士の箱の交差・最小の間隔 | 〔C〕 | P1 |
| 歩いて届くか | 町は道案内の点で確認 | 地形の坂の上限を入れた格子の到達検査 | 〔C〕 | P1 |
| UE の PCG Framework | 無し | UE を使う場合のみ。5.7 で正式版（検索要約） | 〔S〕〔M〕 | P3 |

## 4. 写実の描画
| 機能 | 現状 | 必要なもの | 誰 | 優先 |
|---|---|---|---|---|
| PBR 材質（色・法線・粗さ・AO） | 無し（トゥーン） | `MeshStandardMaterial`＋素材の読み込み（KTX2 圧縮） | 〔C〕 | P1 |
| 光の焼き込み（ライトマップ・AO マップ） | 頂点の安い AO だけ | Blender で焼いて glTF に入れる（ブラウザで写実に近づける要） | 〔S〕 | P1 |
| 環境光（HDRI・反射） | 無し | 夕暮れの HDRI（CC0）を PMREM で | 〔C〕〔M〕 | P1 |
| 霧（高さの霧・遠景） | 距離の霧はある | 高さで薄くなる霧・光の散乱（簡易） | 〔C〕 | P1 |
| 昼夜・夕暮れ | 空のドームはある | 時間 → 太陽の向き・色・霧の色 | 〔C〕 | P2 |
| 雨・濡れた地面 | 雨の粒・水たまりの絵 | 濡れで粗さを下げ色を暗く・水たまりの反射 | 〔C〕 | P2 |
| ホラーの照明（懐中電灯・ちらつき） | 懐中電灯はある | 影つきのスポットライト・ちらつき | 〔C〕 | P1 |
| 性能の計測 | 描画呼び出し・三角形（ソフト描画） | **実機の fps・GPU 時間・VRAM** の記録（`?perf=1` の拡張） | 〔C〕＋実機〔M〕 | P1 |

## 5. AI による設計支援
| 機能 | 現状 | 必要なもの | 誰 | 優先 |
|---|---|---|---|---|
| 日本語の指示 → 配置の JSON | 無し | 地図仕様の形（`07` §5）と、Claude が書く変換の手順・例 | 〔C〕 | P1 |
| 必要素材の一覧・既存素材の検索 | 無し | 素材ライブラリの目録（JSON）を検索する CLI | 〔C〕 | P2 |
| 不足素材の生成計画 | 2D の依頼一覧はある | 3D の依頼項目（寸法・ポリゴン上限・テクスチャ解像度） | 〔C〕 | P2 |
| 生成スクリプト（bpy・UE Python） | 無し | 雛形と生成器 | 〔C〕→実行は〔S〕 | P2 |
| 描画結果と条件の照合・報告・修正案 | 試験と画面撮影はある | 条件の表（例：「霧がある」「入れる家が 3 軒」）を自動で点検し、目で見る項目は人へ | 〔C〕〔M〕 | P2 |

## 6. n8n・AI チーム
| 機能 | 現状 | 必要なもの | 誰 | 優先 |
|---|---|---|---|---|
| 仕事の列・状態 | 無し | n8n（利用者の PC）か、Git 上の `jobs/*.json` | 〔M〕導入＋〔C〕手順 | P3 |
| 承認 | PR のレビュー | n8n の待機（フォーム）か GitHub の PR 承認 | 〔M〕 | P3 |

| PC の性能で仕事を割り振る | 無し | PC の能力の表（`tools/survey_local.ps1` の結果）＋仕事の要求 | 〔C〕〔M〕 | P3 |

## 7. 素材ライブラリ
| 機能 | 現状 | 必要なもの | 誰 | 優先 |
|---|---|---|---|---|
| 3D 素材のメタデータ | 無し（キャラの表に license 欄だけ） | `07` §3 の JSON スキーマ | 〔C〕 | P1 |
| ライセンス門（不明は使わない） | 無し | 検査スクリプト（不明・商用不可・再配布不可を止める） | 〔C〕 | P1 |
| 置き場所（原本・書き出し） | 無し | 原本は NAS／外付け、ゲーム用の軽い書き出しだけ Git（`07` §2） | 〔M〕決定＋〔C〕 | P1 |
| 使用履歴（どの作品で使ったか） | 無し | 目録の `usedBy`＋変更履歴 | 〔C〕 | P2 |
| 素材の最適化（圧縮・LOD） | 無し | gltf-transform（npm）で KTX2/Meshopt・LOD | 〔C〕（素材がクラウドに来れば） | P2 |

## 8. このクラウドでは原理的にできないこと
- GPU を使う描画・焼き込み・UE の起動・Gaea の実行（GPU なし・Windows 専用ソフト）。
- 素材サイト（Fab・Poly Haven・ambientCG）からの取得（通信の規則でブロック）。
- 実機の fps・見た目の最終判断。
→ これらは〔S〕〔M〕として利用者の PC 側の手順に落とします。
