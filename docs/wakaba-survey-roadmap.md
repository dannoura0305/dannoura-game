## 2. 実装済みの機能（指示書に関係するもの）

- **作品をまたぐ読み取り**
  - 本編のエンディングと境界事象の TRUE END がそろうと、本編に DAY 31 が出る（`main/day31.js`）。
  - 境界事象と境界侵食は、本編のセーブを読むだけ（書き込まない）。
  - 境界侵食は `wakaba_progress_v1` も読む。
- **トビネズミのアカウント**
  - 独自のアカウント制（ユーザー名とパスワード、scrypt、30日間有効なトークン）。
  - Origin の許可リスト、接続数とメッセージ数の制限。
  - 10人の負荷試験は済み。公開はしていない。
- **30日分の記録**
  - 成長履歴 `gs.growHistory`（最大30件）。
  - 物語の選択の記録 `gs.story.log`（最大60件）。
  - きずなの記録 `gs.homeData.bonds` と `evaluate()`。思い出帳の「この30日」画面に出る。
  - 結果画面には、診断 `calcPsychType` と最終の数値6項目が出る。
- **ゲームパッド**
  - 対応しているのは runner_hard（`padInput`）と境界侵食（`core/input.js`、`ui/padnav.js`）。
  - 本編、shooter、境界事象、ノアリスは対応していない。
- **shooter のボタン**
  - 長押しで撃ち続ける。
  - 横長の画面では、ボタンを左右の余白へ移す（`layoutWide`）。
  - プレイ中は必ずボタンを出す。
- **runner_hard の演出**
  - 動く背景 `AMB`：花びら、風、電気、滝、雷、水面。
  - 仕掛け、敵、当たり判定は別のモジュールに分かれている（`runner/act`・`combat`・`enemies`・`bosses`・`gimmicks`）。
  - **背景の演出は `runner_hard.js` の中に直書き**で、ほかのゲームから使える形にはなっていない。
- **季節**：ゲーム内の日数で決まる（`main/home/seasons.js`）。現実の日付は使っていない。

1. **プロフィール（端末の中だけ）**
   - 新しい鍵 `wakaba_profile_v1` に、呼び名と誕生日（入れなくてもよい）、血液型（入れなくてもよい）を入れる。
   - 入力しなくても全作品が遊べること。
2. **占いの計算部品（`fortune/`、DOM を使わない純粋な関数と試験）**

   - 四柱推命は、節入りの表が要る。
   - 足りない入力がある方式は「出さない」。
3. **万象堂の画面**
   - 方式ごとの結果を並べる。
   - 複数の方式で一致したところと、食い違ったところを見せる。
   - 「娯楽です」と書く。
4. **本編の日ごとの記録 `gs.dayLog`**
   - 1日1件ずつ足していく。
   - エンディングの判定には使わない。
   - 結果画面に推移の分析を足す。
5. **shooter の入力モード**
   - 最後に使った機器で自動で切り替える。
   - 手動の設定を作る。
   - ゲームパッドに対応する。
   - パッドが外れたらタッチに戻す。
6. **演出の部品化（`effects/`）**
   - runner_hard の `AMB` を、背景・演出・仕掛け・当たり判定の4層に分けて外に出す。
7. **だんのうらの町**
   - 既存の入口（本編、境界事象、トビネズミ、境界侵食、ノアリス、万象堂）をまとめる拠点ページ。
8. **共通アカウント（外部サービス）**
   - Supabase Auth（Google）。
   - `profiles` と `event_claims`（`UNIQUE(user_id, event_id, year)`）の2つの表。それぞれに RLS（行単位の権限）を付ける。
   - 日付は Postgres の関数で `Asia/Tokyo` を基準に決める。
9. **同時接続の検証**
   - トビネズミの既存のサーバーと Cloudflare Durable Objects を比べる試作を作る。

## 6. 無料サービスで実現できる範囲

確度の印は次のとおり。

- ✔：公式ページの抜粋で確かめた。
- △：第三者の情報、または確かめていない。

このセッションからは公式サイトを直接開けなかった。数値は、契約の前にもう一度確かめてほしい。

| サービス | 無料の範囲 | 向いている用途 |
|---|---|---|
| Supabase Auth | ✔ 月に使う人 5万人まで。Google ログインも追加料金なし（△） | 共通アカウント |
| Supabase DB | ✔ Postgres 500MB。△ 通信量 5GB/月 | プロフィール、受け取りの履歴、クラウド保存（小さいもの） |
| Supabase Realtime | ✔ 同時接続 200、200万通/月。上限で止まる | チャットや在室表示なら足りる。**位置の同期には足りない**（20人が毎秒10通送ると約3日で使い切る） |
| Supabase の注意 | ✔ 1週間使われないと一時停止する。無料で動かせるのは2つまで | 定期的にアクセスするなどの対策が要る |
| Cloudflare Workers | ✔ 10万リクエスト/日、1回の CPU は 10ms。上限で止まり、課金はされない | 日付の判定 API、軽い処理 |
| Cloudflare Durable Objects | ✔ 無料プランでも使える（SQLite 版のみ、合計 5GB）。WebSocket の休止機能を使えば、待っている間は課金されない。△ 細かい上限は確かめていない | **同時接続の第一候補**。部屋ごとに1つのオブジェクト |
| Render Free | WebSocket は使える。15分でスリープし、ディスクは消える | 試験のみ。SQLite を使うトビネズミの本番には使えない |
| Fly.io | △ 新しいアカウントには無料枠が無い（トビネズミの文書の見積もりは月 300〜500 円の有料） | トビネズミの今のサーバーをそのまま動かすなら有料 |

**結論**

- アカウント、誕生日、イベント、占いの保存は **Supabase の無料枠で収まる**。
- 同時に遊ぶ機能は、次のどちらかになる。
  - **Cloudflare Durable Objects の無料枠で作り直す**（サーバーのコードを書き直す必要がある）。
  - **トビネズミの今のサーバーを有料で動かす**。
- 占いと町は外部サービスなしでも作れる（端末の中だけで完結する）。

## 7. 想定されるリスク

1. **セーブの互換性**
   - 本編は `version > 1` のセーブを壊れていると見なして拒否する（`game.js:2393`）。
   - 読み込むときに、`Data` で終わるのに無い鍵を消す（`saveDataToGs`）。
   - 新しい欄を足すときは、**version を上げずに足す**。足した欄は、無くても動くように作る。
2. **同じオリジンの共有**
   - `dannoura0305.github.io` の下には別のリポジトリ（game-book-01、novel-01 など）の Pages も置ける。それらからも同じ localStorage が読める。
   - ログインのトークンの鍵は、名前を決めて明示する。
3. **個人情報**
   - 誕生日は、端末の中だけに置くことを既定にする。
   - クラウドへ送るのは、イベントの判定に要る「月日」だけにする（年は要らない）。
   - 利用目的と規約が無いまま公開しない。未成年が遊ぶ可能性もある。
4. **時計のずれと不正**
   - 端末の時計は変えられる。
   - 報酬の受け取りは、サーバーの時刻（`Asia/Tokyo`）と、DB の重複禁止（UNIQUE）で守る。
5. **占いの計算の正しさ**
   - 四柱推命と九星は、年の境目が立春（2月4日ごろ）で、月の境目が節入り。
   - 西洋占星術で太陽星座より先（月の星座など）を出すには、天体暦が要る。
   - 方式ごとに試験の表を用意する。
6. **無料枠の変更と停止**
   - Supabase の一時停止。Cloudflare の条件変更。
   - 外部サービスが落ちても、**ゲーム本体は遊べる**作りにする（ログインは追加の機能として扱う）。
7. **Service Worker のキャッシュ**
   - 外部 API の応答をキャッシュしてはいけない。`sw.js` の対象から外す確認が要る。
8. **並行作業のぶつかり**
   - `sw.js` の `VERSION`、`index.html`、`game.js` は、複数の作業が同時に触りやすい。
9. **外部のライブラリ**
   - supabase-js などは、版を固定してリポジトリに同梱する。
   - 境界侵食の `vendor/` の方式にならう。CDN に頼らない。
10. **容量**
    - リポジトリは 241MB ある。GitHub Pages の目安は 1GB。大きい素材は増やさない。

## 10. 制作者本人の判断が必要な事項

1. **アカウントのサービス**：Supabase（Google ログイン）でよいか。プロジェクトを作るのは本人の Google アカウントになる。
2. **同時接続**：次のどちらにするか。
   - Cloudflare DO で作り直す（無料、手間が大きい）。
   - トビネズミの今のサーバーを Fly.io などで有料で動かす（月数百円、手間が小さい）。
3. **誕生日の扱い**
   - どこまで持つか（月日だけか、生まれた年までか。生まれた時刻と場所も持つか）。
   - クラウドへ送ってよいか。
4. **占いの方式**：入れる方式と優先順。
   - 四柱推命と西洋占星術を、どこまで深く出すか（太陽星座だけか）。
   - タロットの絵（仮の絵でよいか）。
5. **だんのうらの町の形**：どれにするか。
   - 2D の地図を歩く。
   - 一枚絵にボタンを置く。
   - 今のタイトル画面を広げる。
6. **規約と連絡先**：公開するときのプライバシーポリシーの文面、問い合わせ先。
7. **ノアリスの入口**：町から入れるようにしてよいか（今は本編から入口が無い）。
8. **日付イベントの中身**：誕生日に何がもらえるか。ほかの記念日を何にするか（タイムゾーンは日本時間でよいか）。
