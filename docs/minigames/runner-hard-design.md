| 登録・一覧 | `minigames/registry.js` 77 行（名前・説明・曲 `mg_runner`）。スキル `chores`（家事効率）が効く（51 行） |

### 1-2. 流れ（`phase`）
`story`（会話）→ `title` → `run`（走る）→ `arrive`（到着）または `fall`（転倒）→ `home`（家の会話）→ `grade`（評価）→ `mg.end()`

### 1-3. 動き（`updatePlayer`）
- **自動で進む**ランナー。横は `cam += speed*dt`（220＋後半で最大＋150）。自機の横位置は画面上で固定（`PX = 72`）
- ジャンプ：初速 560、2 段目 520。長押しの 0.22 秒は重さ 950、それ以外は 2300。床から落ちた直後の猶予 `coyote` 0.09 秒・先行入力 `jumpBuf` 0.14 秒
- スライド：0.55 秒（押し続けると最長 1.1 秒）。空中で押すと急降下（`fastFall`）してから着地でスライド
- 縦は `py`（上が＋）・`vy`。**床は高さ 0 の 1 枚だけ**（段差・壁・天井の当たりは無い）

### 1-4. 当たりと障害物
- 自機の箱：横 ±7（スライド中 ±13）、高さ 48（スライド中 21）。見た目より少し小さい
- 障害物：`box`・`stack`・`bike`・`cat`（下をくぐれない）／`sign`・`gate`（上をくぐる＝スライド）／`car`（向かって来る）／`puddle`（減速だけ）
- 配置：`placePattern`・`spawnAhead` で、進むにつれて先に作る（**決まった面の地図は無い**。区間 3 つは距離で切り替え）
- 被弾：傘の耐久 `hp` が減る・無敵 `invul`・ヒットストップ。0 で `fall`

### 1-5. 難しさ
- 既に **やさしい／ふつう／むずかしい** がある（`mgDifficulty()`・選択画面で選ぶ・`localStorage`）。むずかしい＝傘の耐久 3・間隔が詰まる 等
- 一度クリアすると「近道（リミックス）」ルートになる（`REMIX`）

### 1-6. 本編との連携・セーブ
- 記録：`gs.runnerData = {plays, clears, best, bestTime, bestCoins}`（本編のセーブ `gs` に入る）
- 結果：`result()` が `fx`（育児ストレス・精神・お金・疲労）・時間・ログ・カットインを返し、本編の 1 日が進む。1 日 1 回（`playedMinigameToday`）
- 本編のイベント「👶 子どもが発熱」（`game.js` 1624 行）があるが、ミニゲームとはつながっていない

### 1-7. そのまま使える物
| 使える | 使い方 |
|---|---|
| 背景の事前描画（3 区間の雨の町）・雨・稲光・電車 | 横スクロールの背景に。カメラを自機に合わせて動かすだけ |
| 主人公の関節の絵（`drawFigure`・`setPose`）・傘 | 新しい姿勢（ダッシュ・壁ずり・斬る）を足す |
| 効果音の合成・パーティクル・ポップアップ・ワイプ・会話（`startDialog`）・家の場面・評価 | ほぼそのまま |
| 障害物の絵（`drawObstacle`） | 面の飾り・壊せる物として |
| 結果の返し方（`result()`）・記録 | 高難易度版の記録を別の欄に |

### 1-8. 技術的な課題
1. **ファイルが 1 つに閉じている**：状態がすべて `start()` の中の変数。高難易度版を同じ所に足すと、通常版を壊しやすい
2. **床しか無い**：壁・段差・天井・足場の当たりが無い（壁蹴りに必要）
3. **自動スクロール**：自由な左右移動・後ろへ戻る・ボス部屋の固定画面に、カメラの作りを変える必要がある
4. **時間の進め方**：`dt` を掛ける可変の歩み。受け取った数値どおりに動かすには **1/60 秒の固定の歩み**が要る
5. **縦長の画面**：横スクロールのアクションには見える範囲が狭い（横 340 の基準）
6. **入力**：同時押し（移動＋ダッシュ＋ジャンプ＋攻撃）がタップ 1 つでは足りない。スマホの仮想ボタンとゲームパッドが要る
7. **1 日 1 回**の枠：何面もある本格的なアクションとは合わない（§7）

## 2. 高難易度版の全体構成案

**方針：通常版のファイルに手を入れず、別のファイルにする。** 共通の絵と音だけを切り出して両方から使う。

```
minigames/runner.js            通常版（今のまま。共通部分を読むように少しだけ直す）
minigames/runner/common.js     共通：背景の事前描画・主人公の関節の絵・傘・雨・効果音・会話・ワイプ・家の場面
minigames/runner/hard.js       高難易度版の本体（場面の流れ・カメラ・HUD）
minigames/runner/act.js        自機の動き（状態の表・1/60 固定の歩み）※DOM なし・node で試験できる
minigames/runner/moves.js      技のデータ（基本技・習得技・コンボの表）
minigames/runner/bosses.js     ボスのデータと AI（行動の表）
minigames/runner/stages.js     面のデータ（タイルの地図・敵・飾り）
tests/runner-hard-*.test.mjs   動きの試験（test_vectors.json と比べる）・技・ボス・セーブ
```

- **入口**：最初は registry に別のミニゲーム（例：`id:'runner_hard'`・名前は仮）として足す案と、通常版の選択画面に「高難易度版」を出す案がある（§9）
- **共通化は段階的に**：最初は高難易度版の中に必要な絵を写して作り、動いてから共通ファイルへ寄せる（通常版を先に触らない）

### 場面の流れ（案）
```
導入（会話：子どもの熱）→ ボス選択 → 面（横スクロール）→ ボス戦 → 技の習得 → ボス選択へ戻る
                                     ↓ 全員倒した
                    帰宅（会話：看病）→ 数日後 → くしゃみ → WARNING → 隠しボス → 結末（勝ち／負け）
```

## 3. アクションシステムの設計案

### 3-1. 固定の歩み
- 1 フレーム＝1/60 秒で回す。`acc += dt; while (acc >= 1/60) { step(); acc -= 1/60; }`（余りは次へ持ち越す・1 回に最大 5 歩）
- 1 歩の順番（受け取った手引きどおり）：①入力で状態を変える ②落ちていれば縦の速さを上限で止める ③重さを引く ④位置に速さを足す ⑤壁・床との当たりを直す
- 単位：受け取った値の「ゲームの値（×2.5・仮想の高さ 560）」をそのまま使う

### 3-2. 状態の表
状態ごとに「入った時に 1 度だけする準備」「毎フレーム」「移れる先」を表で持つ。むずかしさの調整は表の書き換えで済む。

| 状態 | 主な値（ゲームの単位） | 移れる先 |
|---|---|---|
| 立つ | — | 歩き出し・歩く（歩き直しの猶予中）・上がる・ダッシュ・落ちる・攻撃 |
| 歩き出し | 150 px/s を 5 f | 歩く・立つ・上がる・ダッシュ・落ちる・攻撃 |
| 歩く | 220 px/s（加速なし） | 立つ・上がる・ダッシュ・落ちる・攻撃 |
| ダッシュ | 519 px/s・最長 33 f | 止まり際・上がる（ダッシュジャンプ）・落ちる・攻撃 |
| 止まり際 | 8 f | 立つ・歩く・上がる |
| 上がる | 初速 799・重さ 2250・離すと縦 0 | 落ちる・壁ずり・着地・空中攻撃 |
| 落ちる | 上限 863 | 着地・壁ずり・空中攻撃 |
| 着地 | 4 f | 立つ・歩く・上がる・ダッシュ・攻撃 |
| 壁ずり | 8 f 止まる → 300 px/s | 壁蹴り・落ちる・着地 |
| 壁蹴り | 溜め 5 f → 押し出し 8 f（横 220／ダッシュ中 519・縦 799） | 上がる・落ちる・壁ずり |
| やられ | 後ろへ 81・上へ 300・無敵 60 f | 落ちる・着地 |
| **スライディング**（今の作りから） | 0.55 秒・低い当たり | 立つ・上がる |
| **攻撃**（§5） | 技の表から | 技の表のキャンセル先 |

- **今の動きとの関係**：今の 2 段ジャンプは、高難易度版では最初は使わない（習得技の候補にできる）。スライディングは低い当たりの動きとして残す。先行入力（`jumpBuf`）と床から落ちた直後の猶予（`coyote`）は、元の作品にあるか未確認なので、**やさしさの調整として残せる設定**にする
- **試験**：`act.js` を node で動かし、`test_vectors.json` の 5 つ（押したまま・8 f で離す・ダッシュジャンプ・落ちる速さ・壁蹴り）と ±1 f で比べる

### 3-3. 当たり
- 面は**タイルの地図**（1 マス 40 px）。床・壁・天井・すり抜け床（上からだけ乗れる）・とげ（やられ）
- 自機の箱は今の大きさ（横 ±7・高さ 48、スライド中は高さ 21）をそのまま使う
- 横 → 縦の順に動かして押し戻す。壁に当たったらダッシュを止める・壁ずりに入る判定に使う

### 3-4. 入力
| 操作 | キーボード（案） | ゲームパッド（案） | スマホ（案） |
|---|---|---|---|
| 左右 | ←→／A D | 十字・左スティック | 左下の仮想スティック |
| ジャンプ | Z／Space | A | 右のボタン |
| 攻撃 | X | B（X） | 右のボタン |
| ダッシュ | C・↓＋ジャンプでも | R・L | 右のボタン（または 2 回押し） |
| スライド | ↓ | 下 | スティックを下 |
- 入力は「押した瞬間」「押している」「離した瞬間」を毎フレーム作る層を 1 つ置き、技の判定はその層だけを見る
- ゲームパッドは `navigator.getGamepads()` を毎フレーム読む（本編の他のミニゲームには無いので、この版で新しく作る。境界侵食の `shinshoku/core/input.js` の作りを参考にする）

### 3-5. 画面
- 縦長のままだと前が見えない。**横持ちを勧める**表示を出し、横長のときは見える幅を広げる（仮想の高さ 560 は同じ・横は画面に合わせる）
- 縦持ちでは見える範囲を少し引く（縮める）案も検討（§9）

## 4. ボス選択・ステージ管理の設計案

### 4-1. データの形（人数・順番・面の数を自由に変えられる）
```js
// bosses.js（例。名前・見た目・技はすべて仮）
export const BOSSES = [
  { id: 'boss_a', name: '（未定）', stage: 'stage_a', teaches: 'move_a', hidden: false, order: null, reason: '（未定）' },
  { id: 'boss_b', ... }, { id: 'boss_c', ... },
  { id: 'cold', name: '風邪菌（仮）', stage: 'stage_cold', teaches: null, hidden: true, unlock: 'after_all' },
];
```
- 選択画面は `BOSSES` から隠しボスを除いて並べる。人数が変われば並びも変わる
- `order` を入れれば順番固定、`null` なら自由に選べる
- 面は `stages.js` の地図データ（文字の行で書く。境界事象の地図データと同じ書き方）
- **現時点ではボスの中身を一切決めない**。雷雲・濁流・暴風の案、3 か所で材料を集める案は使わない。最初の試作は「仮のボス 1 体」で仕組みだけ確かめる

### 4-2. 1 面の流れ
入口 → 道中（障害物・敵・壁蹴りの縦穴など）→ ボス部屋の扉（画面固定）→ ボス戦 → 倒す → 技の習得の演出 → 選択画面へ

### 4-3. 進み具合の保存
- 本編のセーブ `gs` に別の欄 `gs.runnerHard = { v:1, beaten:[], moves:[], coldUnlocked:false, coldResult:null, best:{} }`
- 通常版の `gs.runnerData` には触らない
- 途中の面の中では保存しない（ボスを倒した時・面を出た時に保存）

## 5. 技習得・コンボシステムの設計案

### 5-1. 基本技と習得技を分ける
```js
// moves.js（例。技名・中身は仮）
export const MOVES = {
  slash1: { base: true,  input: 'atk', on: ['stand','walk','land'], startup: 4, active: 3, recover: 10,
            hit: { box: [8, -40, 46, 36], dmg: 10, hitstop: 4, push: 40 }, cancel: { slash2: [7, 14], jump: [9, 16], dash: [9, 16] } },
  slash2: { base: true,  ... cancel: { slash3: [...] } },
  slash3: { base: true,  ... },
  air:    { base: true,  input: 'atk', on: ['jump','fall'], ... },
  move_a: { base: false, input: 'up+atk', on: ['stand','walk'], learnedFrom: 'boss_a', ... },   // 例：切り上げ（候補）
};
```
- **基本技**（最初から）：地上の 3 段斬り・空中斬り（案。何を基本にするかは §9）
- **習得技**（ボスを倒すと）：`learnedFrom` のボスを倒すと `gs.runnerHard.moves` に入り、以降の面で使える
- 候補（未決定）：回転突進・切り上げ・急降下・ダッシュからの連続技・空中から地上へつなぐ技

### 5-2. 気持ちよさのための決まり
- **こま数で書く**：発生・持続・硬直を 1/60 秒のこま数で持つ（固定の歩みなのでずれない）
- **キャンセルの窓**：技ごとに「このこまからこのこままでなら、次の技・ジャンプ・ダッシュに移れる」を表で持つ。コンボは表をつなぐだけで作れる
- **先行入力**：硬直中に押したボタンを 8 こま覚えておき、窓が開いた瞬間に出す
- **当て感**：ヒットストップ（こま数）・敵の押し戻し・小さな画面の揺れ・効果音
- **当たりの箱は技ごと**：自機の向きで左右を反転
- **一度の振りで同じ敵に 1 回だけ当たる**（多段技は技の表で回数を書く）

### 5-3. 試験
- 技の表の形（キャンセル先が実在する・こま数が正）を node で試験
- 「斬る → キャンセルしてジャンプ」が窓の中で必ず出ること・窓の外で出ないことを試験

## 6. 隠しボス「風邪菌」（名前・見た目は仮）の設計案

### 6-1. 位置づけ
- 高難易度版だけの特別な戦い。通常版では出ない
- 実際の病気の仕組みを再現しない。**架空の、病原体をモチーフにしたコミカルな存在**として扱う

### 6-2. 戦いの仕組み（案）
| 要素 | 案 |
|---|---|
| 感染ゲージ | 体力とは別のゲージ。小さな粒に当たる・本体に触れると増える。満タンで負け（「寝込む」結末）。時間・技で少し減らせるかは §9 |
| 攻撃 | 小さな粒を飛ばす（弾ける＝斬って消せる物と、避ける物を色で分ける）・分裂（倒すと 2 つに分かれる小さな分身）・増殖（放っておくと数が増える） |
| 段階 | 体力の 2/3・1/3 で行動が変わる（分裂が増える・速くなる） |
| 習得技を活かす | 例：上に浮かぶ分身は切り上げで、床の分身は急降下で、まとめて払える作り（どの技が効くかはボスと技が決まってから） |
| 演出 | コミカルな見た目と声（合成音）・くしゃみの合図・負けそうな時の汗の表現 |

### 6-3. 演出の流れ（利用者の案のまま）
1. 全員倒した → 帰宅 → 看病の会話 → 数日後、子どもが回復
2. 「よかったわぁ。ようやく元気になってきたじゃない」→「……へっくしゅん！」→「……あら？」
3. 暗転 → **WARNING — 風邪菌襲来！**（帯・点滅・警告音。合成で作る）
4. ボス戦
5. 勝ち：翌朝も家事 →「ふふん、そう簡単に倒れてられないのよ！」→ 子どもは元気 →「父ちゃんは今日も休めない！」
6. 負け：翌朝、だんのうらが布団で寝込む →「……今度はあたしが風邪ひいたわ……」→ 元気になった子どもが枕元に来る

- 家の場面・会話・子どもの顔の絵（`drawHome`・`drawKidFace`・`startDialog`）を使い回せる
- 勝ち負けで本編に何が起きるか（報酬・疲労など）は未決定（§9）

### 6-4. 解放条件（案。どれにするかは §9）
| 案 | 内容 | 良い所 | 気になる所 |
|---|---|---|---|
| A | 通常ボスを全員倒すと、帰宅後の看病の流れでそのまま始まる | 物語として自然 | 隠し要素の「見つける」楽しさが薄い |
| B | 全員倒した後、ボス選択画面の端に小さな「くしゃみ」の印が出る | 見つける楽しさ | 気づかない人がいる |
| C | 全員を一定の評価以上で倒すと出る | やり込みの目標 | 難しい人には見られない |

## 7. 既存システムへの影響と対策

| 影響 | 対策 |
|---|---|
